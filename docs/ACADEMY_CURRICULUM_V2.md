## Operating rules

1. The existing Academy remains the learning/execution-proposal boundary. This curriculum is a registry and progress layer, not another Academy engine.
2. A learned skill must have traceable evidence and a confidence value.
3. Learning progress is durable in `RuntimeStore`; restart must not erase it.
4. Unknown requirements are recorded as skill gaps instead of being silently ignored.
5. A discovered gap never grants permission to execute the requested capability.
6. New knowledge is compared with existing memory/knowledge before becoming a new active capability.
7. When a new implementation replaces an old one, the old implementation must be retired from active ownership; the curriculum records the capability, not a second execution authority.
8. The Academy may recommend what AURELIX should learn next. Governor/Runtime remain the authority for any real-world action.

## Continuous growth loop

`system requirement → gap detection → study objective → research → learning → evidence validation → Academy knowledge → memory/knowledge graph → capability validation → controlled resume → new requirement discovery`.

The catalog is deliberately extensible: the system can discover useful skills that were not present when this document was written, persist the gap, and propose a new learning objective without inventing completion.
